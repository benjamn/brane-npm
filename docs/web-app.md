# Web App (Expo)

The Expo app runs as a web PWA served by the daemon (and optionally via Cloudflare Workers at `brane.organelle.dev`, which serves the app of the `latest` npm release and is deployed only by a release — see [The app ships with the release](releasing.md#the-app-ships-with-the-release)). It provides:

- **Narrative list** — shows all narratives with summary, status, and MCP connection indicator
- **Spawn button** — header button that opens fold picker modal (or spawns directly with 1 fold)
- **Chat view** — message bubbles (blue for operator, gray for agent, pastel for foreign)
- **🎨 Recolor** — a 🦠 menu item that reshuffles the hues foreign speakers wear in one narrative, for when two agents hash to near-identical colors. Hues come from `src/shared/speaker-color.ts` (salt 0 is the palette every narrative has always had; a nonzero salt is mixed in per speaker through a nonlinear finalizer, since seeding the polynomial hash would rotate every equal-length nid by the same amount). The salt is a per-device view preference in `localStorage` (`expo/lib/recolor.ts`), never sent to the daemon; the list card's menu offers the same item and only advances the stored salt. Export sends it along (`&palette=`), so a snapshot shows the palette the operator was looking at
- **🐚 Utility** — a 🦠 menu item, beside 🧬 Twin, that opens the Spawn dialog on its Utility side in that narrative's fold, with the last utility run already picked (the dialog's default is the newest `GET /api/run-history` entry). A shell next to an agent is 🦠 → 🐚 → Run. Offered on every narrative, from the list card's badge too; the dialog's `initialMode` prop is all it adds
- **Terminal view** — live tmux mirroring with ANSI color rendering (ansi_up)
- **Files view** — browse the narrative's fold: directory listing, Shiki-highlighted code (`CodeView`), rendered markdown (`Markdown`), PDFs (`PdfView`, platform-split — the `.web` variant lazy-imports pdf.js), audio on the jukebox (`AudioCard`: a dial that plays, pauses and scrubs; the track keeps playing wherever you go, and its controls appear on the narrative's card in the list — see [The jukebox](files-view.md#the-jukebox)), hex for everything else (`HexView`), and archives as folders — see [Files View Formats](files-view.md#files-view-formats). The bottom bar searches whatever is showing: **🔎 find in file** on code and markdown, and on hex, where the daemon searches every byte (see [Searching the bytes](files-view.md#searching-the-bytes)) (smart-case literal, `:N` jumps to a line, hits painted with the CSS Custom Highlight API so no DOM changes — `expo/lib/findInFile.ts`, rules in `src/shared/find-in-text.ts`). The hit counter is a drum (`HitDrum`, physics in `src/shared/hit-drum.ts`): faces read `3/17` right-aligned so the totals stand in one column, swipe or flick to roll, tap a half to step, Enter / ⇧Enter roll it too. It stops at the ends (rubber-band past them, a bump on a step into them). The page doesn't glide with it: as the drum crosses each detent the page snaps that hit onto the scroller's middle line, so every hit lands where the eye already is, and half a screen of room below the file lets the last hits reach it. Settling with the keyboard down writes `line=` as closing search does; clearing the query takes it back, **🔮 fuzzy path finder** over `/api/files/list` everywhere else. The view picks the mode and the emoji shows it — there is no switch; the query survives navigation and re-runs in the next view's mode. Closing 🔎 on a hit writes its line into the URL. `#L10-L20` line specs deep-link and scroll to a range
- **Now-playing dial** — a list card whose narrative has a track on the jukebox shows the dial under its status word (tap: play/pause, drag round: scrub to the finger's angle, hold: open the file), and nothing else: stop is on the Files card. The narrative's header shows the same dial left of the 🦠 while that narrative holds a track, and the narrative switcher shows it at the right of each such row. Several narratives can each hold a track; starting one pauses the rest, which keep their dials and their places — see [The jukebox](files-view.md#the-jukebox)
- **Markdown link handling** — `MarkdownLinksProvider` (`components/MarkdownLinks.tsx`) is mounted once per screen and supplies `knownNarrativeIds`, `knownProtocols` (defaulting to `useBrane().protocols`), `onNarrativePress`, and `onProtocolPress` to every `MarkdownContent` beneath it, so chat bubbles, Files-tab markdown, and the wiki reader linkify `nid:seq` and `/command` identically without threading props. Nested providers override only the fields they set (the wiki modal wraps itself to close before navigating); explicit props on `MarkdownContent` still win
- **Tabs** — Chat / Terminal / Files. The active tab plus any **pinned** tabs render simultaneously; the set persists per narrative in storage and round-trips through the `tab` and `pinned` URL params. Tapping into a visible pane selects it *without changing which panes are visible* and never unpins anything — a pin comes off only through its 📌 (`selectPane`, `src/shared/pane-layout.ts`), and a press on a control — a quick key, a menu, a copy button — selects nothing at all: selection runs on `pointerdown`, so a pane that widens under the finger slides the button away before the release, and the tap that caused it is never delivered as a `click`
- **Phone landscape** — a phone held sideways has ~440pt of height, and the stacked header (id, meta line, summary) took ~72 of it. There the header is hidden (`display: none`, so rotating back finds it as it was, an open 🦠 menu included) and the tab bar is the top row, pins and split panes as ever; the header's controls wait for portrait. The gate is the *device*, never the window's shape: a phone-class `screen` (short side < 500), `(pointer: coarse)`, **and** landscape — all three (`isPhoneLandscape`, `src/shared/phone-landscape.ts`, pinned by `src/test/phone-landscape.test.ts`). Desktop keeps its header at any window size, and so do tablets and phones in portrait
- **Quick bar** — `🎹 | 🥫 🦾 | Esc 1 2 3` (`QUICK_KEYS`, `expo/components/TerminalPane.tsx`). `Esc`, `1`, `2`, `3` stay inline because they answer Claude Code's numbered prompts from a phone, where a menu would cost a tap on the most frequent action. 🎹 opens the software keyboard *above* the bar, so the bar stays anchored. 🥫 is the macro menu (`MACROS`, `MacroMenu.tsx`): canned lines typed into the session — `live loop`, `live loop (full)` (the kickoff prompt), `narrate more`, `continue if unblocked`, `/ramify`; the first is the nudge the protocol says an agent must heed whatever it is doing. 🦾 is the controls menu (`COMMON_CONTROLS` and `NAV_CONTROLS`, `ControlsMenu.tsx`), keycaps with operator-chosen hints that stay open so a control can be repeated (paste and clear close it, since the point is to see the terminal):

  | Keycap | Does | Sends |
  |---|---|---|
  | `^C` 🛑 | cancel / interrupt | `C-c` |
  | `^O` 🪗 | verbose transcript (also refreshes the mirror) | action |
  | `^T` ✅ | toggle todos | `C-t` |
  | `^V` 📋 | paste clipboard | action |
  | `⇧⇥` 🚦 | cycle permission mode | `BTab` |
  | `^B` 😶‍🌫️ | background task | `C-b` |
  | `^D` 🪂 | exit (EOF on empty input) | `C-d` |
  | `^J` ↩️ | newline without submitting; the phone's newline, since the 🎹 keyboard's Shift only swaps glyphs | `C-j` |
  | `^L` 🧹 | clear / redraw | `C-l` |
  | Home ⏫ · End ⏬ · Page ⬆️ · Page ⬇️ | scrollback | `C-Home`, `C-End`, `PPage`, `NPage` |
  | Clear 🧽 | clear scrollback, keep the screen | action |

  `^R` history search and `^G` external editor were dropped: keyboard-shaped actions nobody reaches for from a touch menu
- **Full software keyboard** — multitouch with sticky/held modifiers
- **Live updates** — control WebSocket pushes `status`, `meta`, and `new_events` hints
- **Archive/unarchive** — from the 🦠 menu, on a list card's status badge or in the narrative's header. Archive is offered only once the session has ended (the same test that swaps End for Revive); Unarchive on any archived narrative. Archiving from the header goes to the list as a jump, so Back returns — see [View URLs](view-urls.md)
- **The 🦠 menu stays open** after the items that act in place: 🫠 End, 🐦‍🔥 Revive, 🗄️ Archive / 📂 Unarchive and 🎨 Recolor (`keepOpen` in `src/shared/narrative-menu.ts`, pinned by `src/test/narrative-menu.test.ts`), so End then Archive is two taps, as 🦾's keycaps can be pressed in a row. Items that open a dialog or another tab (Meld, Isolate, Export, Twin, Utility, and a Revive that twins) close it, since an open menu's outside-tap catcher would swallow the dialog's first tap. A menu also closes when its screen loses focus (`ContextMenu`), because screens behind the top stay mounted and their catcher would otherwise eat the first tap on the screen in front. End and Revive from a list badge go to the terminal, and the menu goes with them: the narrative's own 🦠 is open on arrival (`src/shared/menu-handoff.ts`, a one-shot slot that expires, not a URL param, so a reload or Back doesn't reopen it). The same goes for a Revive that continues under a new nid
- **Payload rendering** — inline display of image payloads in chat. Tapping one opens the lightbox (`expo/components/Lightbox.tsx`), which steps through every image loaded in the chat, oldest first and straight across message boundaries, without closing: ‹ / › buttons, the ← / → keys, or a horizontal swipe, with a `3 / 12` counter. There's no wrap-around. Tapping anywhere else, ✕ or Esc closes it. The list is worked out only while the lightbox is open, so older history paged in meanwhile lengthens it; the rules are `src/shared/lightbox-gallery.ts`. An image opened from the Files view shows alone
- **Video payloads** — `.mp4`, `.m4v`, `.mov` and `.webm` play in the chat in the browser's own `<video>`: native controls, `playsInline` so iOS doesn't go straight to fullscreen, `preload="metadata"` and a `#t=` fragment so iOS paints the first frame. A download link sits beside each one, for a codec the browser can't play. Videos are their own table in `src/shared/payload-inline.ts` (`VIDEO_PAYLOAD_MIME`), not inline payloads: the lightbox skips them, and the HTML export leaves them as links rather than embedding megabytes as data URIs. The daemon serves them without `Content-Disposition: attachment`, and streams every payload with `Range` support (`src/daemon/payload-serve.ts`), because Safari won't play media until its `bytes=0-1` probe gets a 206
- **Export** — download a narrative as standalone HTML via `/api/narratives/:id/export?format=html`. Foreign rows carry their speaker's hue inline, from the same `speakerColor` / `speakerBgColor` the chat uses, at the 🎨 Recolor salt the device sends as `&palette=` — the one place the salt leaves the browser. With messages selected, the menu offers both sides of the selection — **those messages only**, or the conversation with **those messages left out** — see [Export Scope](export-scope.md)
- **Brane switcher** — dropdown to filter narratives by brane, add/switch daemons. Each row has a ⋯: **Archive** on a brane (on the daemon, for every device — see [Multi-Brane](multi-brane.md#archived-branes)), on another daemon, and, as "Archive this daemon", on the All branes row, which is the active daemon's. An archived daemon stays on this device with its token but is never connected to; **Show N archived** lists archived branes (**Unarchive**) and daemons (**Reconnect**, or **Delete…**, which signs this device out of the daemon with `POST /api/token/forget` and then forgets it). Each brane row (and "All branes") shows its running metered cost as `$2441.72 (138) + 100.2 AIC (1)` — one total per unit with the number of sessions it covers, so a per-session figure can be read off without the line asserting one; the list screen re-reads `/api/branes` (debounced) when a cost `meta` arrives, since the total includes archived narratives the screen never loads. **Devices** lists every token on the active daemon (this device, this machine's CLI and agents, each melded device by browser, platform, address and when it was last seen, under the verification gate what last verified it and whether that window is still open, and any meld QR not yet scanned) with a Revoke on each other device; **Sign out other devices**, at the foot of that list, rotates instead — see [Token Rotation](token-rotation.md#the-devices-list). Below the devices, **Passkeys and security keys** lists the credentials that can verify any device, each revocable, marking any that a rename of the machine or the tailnet orphaned, and **Add a passkey or security key** opens the enrollment page on the daemon's own origin — see [Operator Verification](passkeys.md)
- **Lock sheet** — when the daemon's verification gate refuses this device (`403 { verification }`, or a `verify` frame from a socket), a sheet over the app asks for Face ID, Touch ID or a security key. Its Verify opens the daemon's `/verify` page in a new window (the same tab, with a way back, if no window can open); the sheet closes by itself when the proof lands, and every refused request goes again, once. A dropped keystroke does not: type it again. Going to the background ends the window (`POST /api/verify/end`), except mid-hop — see [Operator Verification](passkeys.md#the-hop)

**Search** (🔬 on the list) runs `searchNarratives()` and `searchWiki()` (`/api/search`, `/api/wiki/search`) side by side. Each hit's snippet is windowed onto where the query matched, with the matches painted, from offsets the daemon's index computes — see [Marking the Hits](memory-search.md#marking-the-hits).

Connection via the URL **fragment**, `#host=<host>&token=<token>` on the shared app and `#token=<token>` on a daemon's own bundle (the legacy `?token=` query form is still read). Tailscale hostname auto-detected by `brane meld`. See [View URLs](view-urls.md) for why the fragment, and for the Expo Router trap it has to dodge. A browser holds daemons from one tailnet only: a link or **+ Add Daemon** entry for a host on another tailnet is refused before anything is sent to it (`src/shared/tailnet.ts`, SECURITY.md, "One tailnet per browser").
